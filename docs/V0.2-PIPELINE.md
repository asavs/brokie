# Brokie v0.2 pipeline

Status: active implementation boundary

## Goal

Given one Git repository seed, produce immutable Scout packets for every listing in
its strongest collection and enqueue those packets for resumable Librarian processing
into one shared catalog.

```text
Git URL or local repository
  -> read-only revision cache
  -> deterministic collection selection
  -> one collection-only ScoutPacket per listing
  -> SQLite Librarian queue
  -> OMP worker
  -> shared candidate catalog and review queue
```

## Responsibilities

- Scout acquires a revision, identifies collection structure, and reports material.
- Deterministic Brokie code performs bulk fan-out. A model never emits 1,200 items.
- OMP owns model authentication, provider mechanics, retries, quotas, and the agent
  session used by the Librarian.
- Brokie owns route permission, the zero-dollar default, typed validation, immutable
  storage, the queue, catalog identity, review, and publication state.
- The Librarian interprets packet material. Passing validation creates a review item;
  it never publishes automatically.

## Route policy

Every OMP job declares its route class as `free`, `quota`, or `paid`. Paid routes are
rejected unless the command explicitly authorizes paid use. Exhausted free or quota
routes fail visibly; Brokie does not silently select another route.

## First acceptance boundary

- A synthetic Git repository produces all expected packets without network or model
  credentials.
- Repeating fan-out reuses identical packets and does not duplicate queue jobs.
- Packet IDs are stable across cache location, selection order, and model route.
- The queue survives interruption and feeds one shared catalog.
- The full `0.1.1`, Scout v0.1, and simplified Scout v0.2 suites remain green.
- One later authenticated run demonstrates OMP against a user-approved route.

Deeper HTTP acquisition, official verification, Planner behavior, and public posting
are not part of this slice.
