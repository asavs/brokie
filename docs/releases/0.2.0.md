# Brokie 0.2.0

Brokie 0.2.0 establishes the first simple repository-to-Librarian pipeline. Given a local or remote Git seed, Brokie can locate a collection, fan it out deterministically into immutable Scout packets, queue those packets idempotently, and pass a bounded batch through an OMP-hosted Librarian into the existing typed catalog and review path.

This is an acquisition and queueing milestone. It does not claim that the full collection has been classified, verified, reviewed, or published.

## Highlights

### Scout now has one small job

- Scout brings back source material; it does not interpret offers, judge authority, resolve identity, reconcile conflicts, or assign catalog vocabulary.
- ScoutPacket v0.2 preserves the exact collection listing, source locator, Git revision, and artifact lineage.
- Packet identity is local to the subject evidence. Companion listings, model routes, budgets, selection order, and unrelated failures do not change it.
- ScoutPacket v0.1 remains immutable and supported by its regression suite.

### A Git URL can become a durable Librarian queue

- Local and remote Git seeds are read at an exact recorded revision, so dirty working-tree bytes cannot be attributed to `HEAD`.
- Brokie selects the strongest bounded Markdown or HTML collection and fans out every listing whose primary source link is an explicit HTTP URL.
- Fan-out is deterministic and does not require a model to select or emit thousands of entries.
- Replaying the same source revision reuses packet identities and does not duplicate queue jobs.
- The live read-only free-for-dev dogfood produced 1,299 stable packets from revision `99d188953fbb2c7c522b97398f4830b91b58016f`.

### OMP is a replaceable worker boundary

- The headless worker uses OMP for authentication, provider mechanics, quota handling, and retries.
- Brokie retains route authorization, typed validation, durable queue state, catalog persistence, review, and publication policy.
- Route classes are explicit: `free`, `quota`, or `paid`. A paid route is rejected unless the individual command opts in with `--allow-paid`; there is no silent paid fallback.
- Interrupted work remains inspectable and can be resumed from the SQLite queue.

### The existing trust boundary still applies

- Librarian output remains a proposal and must pass deterministic normalization and validation.
- Candidate and review state flow into the shared typed catalog rather than a parallel demo store.
- Validation now checks controlled-vocabulary membership by `concept_id`, matching the published schema.
- Nothing is published merely because a model response validates.

## Usage

```bash
npm run pipeline:ingest-v02 -- --seed=https://github.com/ripienaar/free-for-dev --state-dir=var/pipeline
npm run pipeline:librarian-v02 -- --state-dir=var/pipeline --limit=5 --route-class=quota --model=PROVIDER/MODEL
```

Runtime databases, packets, provider responses, credentials, and traces remain ignored local state and are not included in the release.

## Compatibility and operational notes

- The v0.1 Scout contract and tests remain intact; v0.2 is a new acquisition-only contract.
- The earlier unreleased research-heavy v0.2 design is retained in history as evaluation work but is superseded by the simpler boundary.
- OMP is currently an external CLI dependency and is not version-pinned by Brokie.
- The legacy v0.1 Librarian commands, review flow, API, explorer, and fixture builders remain available.
- Node.js 22.13 or newer is required by the current package metadata.

## Verification

- The full lint, contract, store, ingestion, Librarian, API, legacy, Scout v0.1, Scout v0.2, and pipeline v0.2 suite passes without network access or credentials.
- Adversarial coverage verifies Git revision fidelity, stable subject-local packet identity, explicit-link filtering, idempotent queueing, paid-route refusal, structured Librarian handoff, and shared-catalog persistence.
- One live quota-routed Librarian job completed through OMP without paid fallback and reached `review_required` in the durable queue.

## Known gaps

- The remaining 1,298 live dogfood packets have intentionally not been bulk-processed. The current Librarian prompt is roughly 12,000 tokens for a sparse listing and the first live job required its one repair call.
- The first live candidate truthfully created only a product proposal from sparse collection evidence; it did not invent an opportunity. Deeper official-source acquisition is still needed for useful offer records.
- Provider and model failures are expected operational facts. They should be recorded as failures, stubs, or TODOs, not hidden behind Scout complexity or paid fallback.
- The v0.2 collection path currently targets Git-hosted Markdown and HTML. CSV collections, browser automation, arbitrary web crawling, and social-source acquisition are outside this release.
- Queue recovery currently assumes a simple bounded worker workflow; multi-worker leasing and unattended stale-job recovery have not been proven.
- Official verification, change-aware refresh convergence, Planner behavior, deployment, and public or social autonomy remain future work.

## Next

- Make the Librarian smaller: reduce its prompt, simplify the proposal task, and measure repair frequency across several OMP free and quota routes.
- Process and adversarially review a representative batch before resuming the full 1,299-packet queue.
- Let the Librarian request targeted additional Scout material when a collection listing is insufficient.
- Preserve the existing human trust gate while converging accepted revisions into the typed API and explorer.
