# Brokie Librarian v0.0.1 — experiment report

## Outcome

The proof of concept demonstrates the intended UX: a person or agent describes an end goal (for example, “run an AI model” or “get startup cloud credits”) and receives relevant opportunities with inspectable source evidence. The deterministic build selected 54 of 1,566 supplied source records: 44 README entries and 10 startup offers, normalized into 52 products, 94 capability links, and 91 user-need links. Three ambiguous records are explicitly queued for review.

This is an organization experiment, not an availability audit. Every record retains its raw supplied text, file, README line or CSV row, URL, stable source ID, and derivation status.

## Knowledge shape

The SQLite schema separates source records, products, opportunities, requirements, capabilities, user needs, relationships, librarian runs, and review items. That distinction matters: “Google” is a provider, “Colab” is a product, free GPU notebook access is an opportunity, and “train a model cheaply” is the searcher's desired outcome. Search should primarily traverse user need → capability → opportunity, while provider name remains a secondary filter.

The controlled v0.0.1 vocabulary has 18 capabilities and 12 user needs. Deterministic rules create the initial staging index. LLM output is advisory, schema-validated, traceable, and evaluated against a 16-record manually reviewed set.

## Controlled inference results

All successful comparisons used NVIDIA's free endpoint and `nvidia/nemotron-3-ultra-550b-a55b`. Each record received the same supplied source text, controlled vocabularies, JSON contract, no tools, and no persistent memory.

| Harness | Schema valid | Inclusion accuracy | Capability precision / recall | Need precision / recall |
|---|---:|---:|---:|---:|
| Direct API loop | 93.8% | 93.8% | 87.5% / 91.3% | 83.3% / 95.2% |
| Pi SDK, normalized sampling | 87.5% | 87.5% | 72.0% / 78.3% | 72.7% / 76.2% |
| Pi SDK, provider defaults | 100% | 100% | 69.0% / 87.0% | 76.0% / 90.5% |

The direct loop is the best v0.0.1 librarian harness. It is smaller, easier to constrain, exposes token usage, and produced the best balanced label quality. Pi works and is pleasant to embed, but its agent/session machinery adds no advantage to this one-shot classification step. Provider-default Pi happened to produce valid JSON more reliably, while also over-labeling more aggressively; this shows why schema validity alone is an insufficient evaluation.

The evaluator also checks the other safety-relevant outputs: whether each extracted requirement's quoted evidence occurs in the immutable source text, whether important unknowns are preserved, and whether the two reviewed Maxim records propose one another as duplicates. These are deliberately narrow, auditable proxies for unsupported claims and entity-resolution quality; the report does not pretend that a 16-record set establishes general performance.

Hosted-model availability was a real operational finding. NVIDIA returned end-of-life responses for DeepSeek V4 Flash, DeepSeek V4 Pro, and GLM-5.2 even while discovery surfaces still presented some of them. Inkling and Nemotron 3.5 Lightning consumed their output budgets in reasoning without returning the required JSON in tested settings. Therefore Brokie must probe the actual inference endpoint, record resolved model and failure details, and maintain fallbacks rather than trust a model directory.

## Harness decision

For v0.0.1, use the direct loop as the librarian worker. Keep Pi as a compact experimental adapter and regression comparison.

For a later always-on Oracle VM, Hermes is the strongest candidate among the discussed full-agent harnesses. Its official CLI supports native Windows and Linux, one-shot non-interactive prompts, NVIDIA/OpenRouter providers, gateways/cron, memory, skills, and a learning loop. Those are useful for a maintenance supervisor, but they should surround the deterministic pipeline—not become the database or silently rewrite facts. Start Hermes with no publishing credentials and narrowly scoped tools; promotion/social autonomy remains a distinct later system with separate policy and audit controls.

`fx` is compelling as a tiny coding-agent substrate and supports one-shot `fx ask`, native/WASM embedding, permissions, MCP, skills, and subagents. Its documented first-run provider path centers on Vercel login or AI Gateway rather than the clean NVIDIA endpoint used in this experiment, so installing it would not produce a controlled comparison here. Revisit it if AI Gateway becomes an accepted free inference route or if Brokie needs an embedded repository-maintenance agent.

## Recommendation

Ship the next local iteration as three layers:

1. deterministic ingestion and provenance, producing SQLite/JSON;
2. a constrained LLM enrichment queue with JSON validation, confidence/review routing, endpoint probes, and reproducible traces;
3. a read-only need-first web/API surface.

Only after local precision and stale-offer workflows are satisfactory should this move to an Oracle Always Free VM. On the VM, run ingestion and enrichment as idempotent scheduled jobs, serve the explorer read-only, back up the small database, and treat all model providers as replaceable zero-cost dependencies. A full Hermes supervisor can be evaluated then for scheduling, recovery, and maintainer memory. Public posting and social-account control remain out of scope until the underlying catalog is trustworthy.

## Known gaps

- Offer availability, geography, expiry, stacking rules, and eligibility have not been independently verified.
- The 16-record reference set is useful for smoke testing but too small for product-level claims.
- Search is lexical plus controlled filters; embeddings/reranking are unnecessary until the vocabulary and evidence quality stabilize.
- Duplicate detection is represented but not yet a full entity-resolution workflow.
- Free inference endpoints can disappear without warning; successful historical traces are not availability guarantees.
